# 教學原理｜跨週次報告互評與心得回顧（2026-11-22 v3）

> **這是 2026-11-22 v3 版，不是最初的匿名互評版。** 開啟 `index.html` 右上角應看到「v3 學號姓名／跨週心得版」。
> 此 ZIP 中的 `index.html` 與 `Code.gs` 必須一起更新；新版後端回應標記已改為 `v3`，可以避免舊程式與新頁面混用卻誤認完成。


這是一套「**GitHub Pages 學生網頁 + Google Apps Script + Google Sheet**」的課堂互評系統。

學生每次先輸入**學號、姓名**，系統會從 Google Sheet 查詢相同學號與姓名先前留下的心得。開放週次可以選一組報告、寫下 **1–30 字心得**。**每位學號每週限一次，送出後不可修改或重新投票**；已提交的內容會以唯讀方式顯示。

## 一、週次與開放時間

臺灣時間（Asia/Taipei），均為 **2026 年**：

| 報告日 | 開放 | 截止（當日 23:59:59） | 學生選擇的組別 |
| --- | --- | --- | --- |
| 11/23（一） | 11/22（日）00:00 | 11/24（二） | 第1組：工作分析教學法；第2組：協同教學法 |
| 12/7（一） | 12/6（日）00:00 | 12/8（二） | 第3組：探究教學法／講述教學法；第4組：直接教學法 |
| 12/14（一） | 12/13（日）00:00 | 12/15（二） | 第5組：討論教學法；第6組：結構式教學法 |

截止時由 **Apps Script 後端**再次核對開放日期，學生不能只靠更改瀏覽器時間越過限制。網頁也會顯示各週的開放與截止時間。

## 二、建立／更新 Google Sheet

1. 在 [Google Sheet](https://sheets.google.com) 建立一份**私人**試算表，例如「教學原理－課堂報告互評」。不要公開分享編輯權限給學生。
2. 在試算表選擇「**擴充功能 → Apps Script**」，將 `Code.gs` 全部貼入並儲存。
3. 在 Apps Script 頂端函式選單選擇 **`setup`**，點選「執行」並完成 Google 授權。
4. `setup()` 會建立／整理這三個工作表：
   - **互評回覆**：提交時間、報告日期、週次、學號、姓名、獲選組別、主題、30 字心得、提交編號。
   - **統計總覽**：六組獲選票數和當週比例，依回覆表自動計算。
   - **學生名單**：已預載你提供的 **34 位組員姓名**，B 欄「學號（教師可補，建議）」先留空。

**建議教師在「學生名單」B 欄填入每人的正式學號。** B 欄已設成文字格式，可保留學號前面的 0。填妥後學生需要輸入符合名單的學號與姓名才能查詢及提交；未填學號的姓名仍可使用系統，但無法核對那個學號是否正確。若課程還有其他修課學生，請在「學生名單」下方新增姓名。

`setup()` 可重複執行，**不會刪除「互評回覆」與「學生名單」既有內容**。它會重新產生「統計總覽」。舊版的 7 欄匿名回覆如果已經存在，會原樣保留並轉成新 9 欄格式，學號與姓名空白；那些匿名舊回覆無法自動歸屬某個學生。

## 三、部署 Apps Script 接收程式

選擇 Apps Script **「部署 → 新增部署 → 類型：網頁應用程式」**，設定：

- **執行身分**：「我」（教師的 Google 帳號）。
- **存取權限**：「任何人」（Anyone）。

部署後複製以 `/exec` 結尾的**網頁應用程式網址**，它不是 Google Sheet 網址。

若這是從先前版本升級，建議使用「**部署 → 管理部署 → 編輯 → 版本：新版本 → 部署**」更新原有網頁應用程式。只按「儲存程式碼」並不會讓既有 `/exec` 網址套用新版程式。

> 若學校 Google Workspace 不允許「任何人」存取，這種 GitHub 直連模式可能無法運作；請改用校內核可的登入／授權方案。

## 四、發佈 GitHub Pages

開啟 `index.html`，搜尋下列文字：

```js
const WEB_APP_URL = "PASTE_YOUR_GOOGLE_APPS_SCRIPT_EXEC_URL_HERE";
```

把引號中的內容替換成完整的 Apps Script `/exec` 網址後儲存。

- 將 **`index.html`** 放到你要公開的 GitHub repository 根目錄，其他檔案不需要公開。
- GitHub repository → **Settings → Pages** → Source **Deploy from a branch** → branch `main`，資料夾 `/(root)` → Save。
- 分享生成的 GitHub Pages 網址給學生。例如 `https://你的帳號.github.io/你的repository/`。

如果你原本已經有 GitHub Pages，就將舊 `index.html` 直接更新成這一版。**切記 Apps Script 和 GitHub 網頁兩邊都要更新**；新舊版不能混用。

⚠️ **不要把 `Code.gs`、Google Sheet 匯出檔、學號對照表、Google 帳號權杖上傳到公開的 GitHub repository。**

## 五、學生怎麼填？

1. 開啟 GitHub 網頁，輸入學號與完整姓名，點「查看我的互評頁面」。
2. 網頁從 Google Sheet 取得與該學號、姓名相符的歷次紀錄，並顯示三週卡片。
3. 開放期間選擇其中一個組別，填寫 1 至 30 字的心得。選擇時**只顯示組別與教學法主題，不會顯示組員姓名**。
4. 按「送出本週互評」，再次確認後寫入 Sheet，系統即將該週鎖定。學生可看到這一週的原始心得，但無法修改。
5. 下週換手機或電腦再來時，只要再次輸入同樣的學號與姓名，之前的心得會從 Sheet 載入；不依賴瀏覽器 localStorage。

**已填寫週次**會顯示「已填寫」，未開放顯示「尚未開放」，截止後顯示「已截止」。歷次心得會按照報告日期由近到遠排列。

## 六、建議測試方式

1. 在「學生名單」最後一列加入一位**測試用姓名與學號**，例如「測試學生／TEST0001」。
2. 打開學生網頁，使用這組測試資料查詢。若日期在開放期間，送出一筆測試心得。
3. 確認「互評回覆」新增一列、「統計總覽」票數增加，且學生網頁同週變成「已填寫」。
4. 重新開啟網頁，輸入相同學號與姓名，確認能看到先前心得，並且無法再次送出同週資料。
5. 測完後教師可在私人 Sheet 裡刪掉**那筆測試回覆**和**測試名單**，避免計入課堂正式票數。請勿刪除表頭。

若 Apps Script 送出沒有回執，表單會出現「再次確認送出」；該按鈕會使用相同提交編號重試，避免網路重送產生第二筆。請先確認 Sheet 是否已成功寫入，再判定是否有問題。

## 七、資料保護與限制（請教師留意）

- **此版用學號與姓名「辨識」學生，不等於真正登入驗證。** 如果某人知道其他人的學號與姓名，仍可能冒用該組資料查詢心得或代為投票。補上名單的正式學號可防止輸入錯誤、排除無關人士，但**不能完全阻止知道他人學號的人冒用**。
- 若是正式成績評量或對學生個資有較高保護要求，建議升級為**學校 Google 帳號登入**、學校單一登入（SSO），或每人獨立的驗證碼機制。在此之前，宜作為低風險的課堂意見回饋系統。
- 每學號每週至多一筆的限制，由 Apps Script 透過鎖定＋查重執行；換瀏覽器或重開頁面也不能再次填寫。但若刻意冒用不同姓名學號，這套輕量系統無法單憑資料欄位阻止。
- 學生不能透過這個網頁修改或刪除已提交的回覆；**持有 Google Sheet 編輯權限的教師**仍然可以在 Sheet 中管理資料。
- 學號、姓名和心得只送往教師指定的 Apps Script / Google Sheet。網頁不會把學生身分儲存在本機長期保存，換週需要重新輸入。
- 本程式使用公開存取的 Apps Script 網頁應用程式端點；不要將 Google Sheet 設成公開。課程結束後，教師可依學校個資規範保存或清除互評資料。

## 八、怎麼改日期？

如果要延期，**必須同步**修改：

- `index.html` 的 `WEEKS`，每週的 `open` 和 `end`（格式 `yyyy-mm-dd`）。
- `Code.gs` 的 `WEEKS`，同樣的 `open` 和 `end`。

然後重新部署 Apps Script 的**新版本**並更新 GitHub 的 `index.html`。**只改其中一處可能導致網頁顯示可填寫，但後端拒絕寫入。**
